# 绮录QQ聊天记录导出软件 P4 项目书

**审阅稿 · 2026-11-19**

## 阶段目标

在 P3+ 稳定基线上增加更新检测与少量直接服务于导出的功能。延续原设计对语音转码和 PDF 页码的设想，将它们列入可选功能，按样本覆盖、依赖体积和导出质量决定是否采用。[原设计 §13](../specs/2026-10-23-qq-chat-history-export-design.md)

## 首批功能提案

| 任务 | 功能 | 验收条件 |
| --- | --- | --- |
| T01 更新检测 | 优先做手动检查，从项目官方发布渠道获取与当前分发包匹配的公开版本信息，显示版本号和更新说明，提供打开官方发布页入口。自动检查作为可选设置提案，默认关闭。商店版使用 Microsoft Store 的更新机制。 | 测试正式版、候选版、高于服务器版本、离线、超时、服务限流、格式损坏及重复点击。正式版默认识别正式发布，正确排列 `rc2`、`rc10` 和同版本正式版。检测与启动、浏览、导出独立。 |
| T02 导出预设 | 复用现有导出设置，提议保存常用的格式组合与导出位置。调用前仍以用户本次选择的账号、会话和消息范围为准。 | 旧配置顺利迁移。失效目录可重新选择。修改预设对其他账号的数据和历史产物没有写入副作用。 |
| T03 导出结果细节 | 复用现有任务进度及导出结果入口，提议按格式说明哪些产物已写入、哪些降级、哪些失败及下一步如何处理。 | 双格式中单项失败、缺失媒体、PDF 超限、队列取消的结果与实际文件一致。相同内容在批量和单次导出中使用同一套口径。 |

## 可选项

| 提案 | 开工依据 |
| --- | --- |
| PDF 页码 | 样张验证中文、长消息、页边距及图片位置，确认可以复用现有打印路径。 |
| 语音转码 | 先验证本机缓存样本、覆盖格式和分发依赖体积。保留原始音频路径。 |

## 更新与隐私边界

- 更新检测仅发送访问官方发布源所需的普通网络请求，本机比较版本。聊天、账号、文件路径、密钥和诊断内容留在本机。手动检查及可选自动检查的行为同步写进隐私条款。
- 此阶段的范围是检测、展示和跳转。用户从官方渠道取得所需包后自行安装。由用户分别决定更新入口、提示方式及其他新功能涉及的 UI 改动，每项改动前按项目原则保存可恢复原档。[项目协作原则](../../../AGENTS.md)
- 检测失败通过现有错误反馈说明，支持再次检查。可选自动检查与离线启动解耦，安排有限超时、缓存和节流。测试使用模拟响应覆盖成功与失败路径。

## 交付与版本

按「更新检测 → 选定的导出增强 → 同构建验收」推进。交付功能说明、隐私条款差异、迁移验证、包体变化记录和候选分发包。有新增对外能力时拟使用 `0.5.0rc1`，验收后转 `0.5.0`。[版本规则](../../VERSIONING.md)

## T01 实施记录

源码命令 `check-updates` 与冻结内核命令 `--check-updates` 共用版本规则。用户显式调用时才查询公开发行记录。GitHub 正式版只比较正式发布，候选版同时比较两种发布。发生超时、网络错误、限流或响应损坏时，命令给出错误并允许之后重试。检测到内置内核运行在 Windows 应用包身份下时，由 Microsoft Store 负责后续检查。桌面入口和发布隐私条款按 P4 交付范围验收。[桌面开发文档](../../electron-desktop.md#手动检查更新)
