## 一、立项依据

原设计将 P3 定为「PDF 与打磨」，包含 PDF、HTML 分片、导出报告和体积保护。P2 已经实现搜索、批量、增量、归档与本地资料库，Electron 也已接入 PDF 打印。本阶段从现有实现逐项核对缺口。首要问题是 0.4.1 便携版在本机启动验证时提前退出。源码版的合成数据冒烟通过只证明开发入口可用，分发体验需要用实际产物复验。P2 的 Tk 性能记录用于追溯，P3 以 Electron 重测为准。[原设计 §10.3、§13](../specs/2026-10-23-qq-chat-history-export-design.md) · [P2 功能验收](../../P2-feature-status.md) · [交接文档](../../HANDOFF.md)

## 二、项目原则

- 已完成的 UI 布局、样式、组件和操作流程作为验收基线。任何 UI 改动都以用户明确要求为前提，仅改指定范围。动手前在仓库和构建清理目录之外保存可直接恢复的原档，记录提交号、未提交差异、原路径和恢复步骤。完成后复核现有交互，并在交接说明恢复方法。[项目协作底线](../../../AGENTS.md)
- 仅处理用户自有设备与账号数据，源 QQ 数据库、WAL 和媒体保持只读。保留首次启动隐私授权与独立头像联网授权。聊天、媒体、凭据和含私人数据的诊断材料始终留在本机，公共仓库与 CI 使用合成样本及脱敏记录。[隐私条款](../../../privacy.md)
- 本地研发的缓存、临时文件、验收记录和默认导出产物统一放在项目目录，沿用 `.local/`、`build/`、`dist/`。已安装软件沿用现有权限与用户数据约定，继续支持用户指定导出目录。商店身份、签名材料、真实聊天和本地配置留在 Git 之外。
- 按交接规则逐任务提交与推送。修复、性能和封装优化递增版本第三段，新增对外能力递增第二段。任务号与版本号独立，发布时统一同步 Python、Electron、PE 和产物版本，已发布标签与资产保留。[版本规则](../../VERSIONING.md)

## 三、工作拆分

| 任务 | 工作范围 | 退出条件 |
| --- | --- | --- |
| P3-T01 基线与启动修复 | 在隔离配置下复现 0.4.1 便携版提前退出，对照源码入口、完整解压产物和安装版。记录退出码、运行环境和缺失资源诊断，修复根因后冻结测试样本与基线。 | 新产物在无系统 Python 环境正常启动，能显示隐私授权并完成一次合成数据导出。记录原问题和修复后的复验结果。 |
| P3-T02 大会话性能 | 实测账号切换、长群聊首屏、滚轮、拖动滚动条跳转、冷缩略图和首次搜索。按瓶颈调整已有分页、预取、图像解码与后台调度。并发限制根据实测确定，过期请求结果随会话切换失效。 | 按第四节提交冷、热数据。快速跨账号及跨会话操作无串数据，跳转后完成定位，滚动边界和选择状态通过回归。 |
| P3-T03 PDF 与 HTML 大体量导出 | 用现有 Electron PDF 路径覆盖中文、长消息、大图、分页、缺图与取消。核查 HTML 现有分片与体积保护，补齐缺口。需要分片时保留离线入口、顺序和媒体链接。估算体积与可用空间，对超限、磁盘不足和中断复用已有错误或结果反馈。 | 正常文件可离线打开，分片前后消息顺序和数量一致。PDF 普通消息尽量整条分页，超页长消息正文可完整阅读。失败或取消时旧产物可继续使用，重试无重复与残留。 |
| P3-T04 导出报告与离线回归 | 复用现有任务进度和导出结果入口核对报告统计，覆盖 TXT、HTML、PDF、批量、增量、归档和资料库。验证 QQ 退出、网络断开及重启后的本地数据路径，记录已有可用凭据、缺失或失效凭据、媒体未缓存等情形。 | 成功、降级与失败计数相加等于消息总数。已具备有效本机数据与凭据时能离线完成导出。对从未被绮录打开的历史账号实测并明确可用条件，归档离线回归单独留证。诊断不暴露凭据或聊天正文。 |
| P3-T05 Windows 和分发 | 提交级 Windows 测试通过后，在干净环境用同一次构建验证 Windows 10 x64 与 Windows 11 x64。测试安装、启动、卸载、完整解压、中文与空格路径、权限拒绝及隐私条款入包。核对 MSIX 时使用本机商店配置，记录单独的验证结论。 | 每个拟对外声明的系统记录实测发行版、构建号和产物哈希。安装包含卸载，便携版使用随包运行库。Windows 10 的支持范围以真实通过的版本与构建为准。 |
| P3-T06 正式交付 | 汇总功能回归、真机隐私与只读性、性能对照和产物清单。同步兼容矩阵、README 用户说明、项目交接与版本专属发布说明。 | 交付验收表、安装包、便携版与哈希。Release 标题仅版本号，正文包含下载与运行、功能更新（如有）、问题修复（如有）、支持的系统范围。 |

先完成 T01 建立可用测试入口，再推进 T02–T04。T05 使用包含拟发布变更的同源构建，T06 根据实际验收结果收尾。

## 四、验证方案

| 场景 | 验收口径 |
| --- | --- |
| 滚动与跳转 | 以 10 万条合成消息和混合媒体为固定场景，窗口前台测量，至少五轮。P2 的 ≥55 FPS 为目标，记录帧间隔 P95、长帧、随机跳转可读耗时及未完成请求数。鼠标滚轮连续操作和拖动到随机位置分别复验。 |
| 首屏与搜索 | 会话首屏以可读消息出现为终点，参考 P2 的 ≤300 ms。冷缩略图参考 ≤200 ms。首次搜索含索引建立，热搜索另计。冷、热缓存分别记录 P50/P95，同时报告硬件、系统、数据和峰值内存。 |
| 数据完整性 | 使用同一冻结消息选择导出三种格式，逐项核对时间、顺序、回复、图片、文件名、缺失占位、报告计数与同输入重复导出。PDF 的版面与内容单独复核，并在存在字节差异时记录原因。 |
| 本机真实验收 | 经授权用一组私聊和一组群聊验证浏览、离线导出及最新消息，对实际存在可验证提交的 WAL 留证。QQ 退出时比较源文件身份、大小和修改时间。QQ 运行中记录可证实的只读检查与并发写入条件。对外记录仅保留场景、结果和脱敏统计。 |
| 发布复验 | 以同提交、同配置、同包哈希关联 CI、Windows 真机和包体验收。每项标记 PASS、FAIL、SKIP 或未验证，历史通过记录仅作参考。按原设计 §10.3 逐项追踪，工具检查项按当前实际接口对应。[发布检查清单](../../release-checklist.md) |

## 五、里程碑与验收决定

1. **M1 分发入口可复验**。T01 结束后交付启动诊断、修复和基线数据。
2. **M2 核心体验达到候选条件**。T02–T04 结束后交付性能前后对照、三格式导出样本验收和离线回归表。未达的性能目标记录复现条件、影响和后续安排。
3. **M3 正式版证据齐备**。T05–T06 结束后核对分发资产、系统矩阵与发布材料。核心启动、只读性、隐私授权或数据完整性失败时停留在候选阶段。Windows 10 缺少实测证据时标明未验证。

拟按实际交付决定版本。若 P3 只做修复、性能改进和封装收尾，以 0.4.1 源码为基线拟用 `0.4.2`。若最终交付新增用户可用能力，则拟用 `0.5.0`。已知任务的先后次序按上述里程碑执行，日期在 T01 取得实际启动与性能基线后排定。

## 六、T01 首轮记录

- 同一份 0.4.1 ZIP 在本机开发目录启动时以 `0x80000003` 退出，更换为 ASCII 文件名仍可复现。交叉测试中，应用放在可用的程序目录后可以加载项目内的隔离配置。另一处测试目录记录到 Electron 的 `install_dir_access.cc` 启动错误，给该隔离程序副本补齐只读访问权限后通过启动。保留沙箱设置，并在桌面端文档记录目录诊断方法。
- Windows 11 x64 上，源码与更新了测试入口的便携副本均在独立 Windows 测试桌面完成离屏冒烟。便携副本的归档、搜索、TXT／HTML／PDF 和源文件哈希对比通过。测试移除了 Python 的搜索路径和相关环境变量，使用包内冻结内核。原有安装包和 ZIP 文件哈希保持原样。
- 原安装器的安装和卸载均通过。首次启动在隔离安装目录复现相同的 Electron 沙箱访问错误。仅在新建的安装测试目录补齐程序文件读取与执行权限后，未改动的安装产物通过冻结导出链路，随后用原卸载器清理。安装器自动处理目录权限以及 Windows 10 复验留待后续。[Electron 上游说明](https://releases.electronjs.org/pr/54382)
- 离屏单轮采样中，便携副本首条消息显示用时 107 ms，随机跳转测试稳定用时 67 ms，消息滚动帧间隔 P95 为 16.67 ms。以上是合成数据下的测试记录，正式性能验收仍需按第四节执行。
